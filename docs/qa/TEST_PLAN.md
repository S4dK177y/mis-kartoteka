# Test Plan: МИС Картотека

## 1. Введение
Данный документ описывает стратегию тестирования, цели, критерии приемки и тестовое окружение для веб-приложения "МИС Картотека".
Проект представляет собой медицинскую информационную систему для учета пациентов, перевода между отделениями и хранения строго конфиденциальных медицинских данных.

## 2. Область тестирования (Scope)
**Включено в тестирование (In Scope):**
- Модуль "Авторизация" (Логин, выход, проверка сессии, Rate Limiting).
- Модуль "Пациенты" (CRUD: создание, чтение, обновление списка пациентов).
- Управление доступом (Role-Based Access Control) между ролями `Doctor` (Врач) и `Admin` (Администратор).
- Механизмы безопасности и шифрования (Application-Level Encryption - ALE для ГОСТ шифрования БД).

**Не включено в тестирование (Out of Scope):**
- Генерация и парсинг Excel-отчетов (отложено до следующих релизов).
- Аудит логов (Audit Log) - проверяется поверхностно.
- Глубокое профилирование базы данных (только k6 нагрузочные тесты API).

## 3. Виды тестирования (Testing Types)
- **Функциональное тестирование:** Smoke тесты (базовая проверка после деплоя), Sanity тесты (проверка конкретных модулей), Регрессионное тестирование (прогон тест-кейсов в Qase.io).
- **Нефункциональное тестирование:** Проверка безопасности (ALE шифрование, базовые векторы SQLi и XSS), UI/UX валидация (отзывчивость интерфейса).

## 4. Тестовое окружение (Environment)
- **ОС:** Windows / Linux
- **Браузеры:** Google Chrome (последние версии), Safari (опционально).
- **Среда:** Локальный контур на базе Docker Compose (`http://localhost`).
- **База данных:** PostgreSQL 15+ (внутри Docker контейнера `mis_db`).
- **Мониторинг:** Prometheus + Grafana (для контроля ресурсов во время тестов).

## 5. Критерии старта и окончания (Entry & Exit Criteria)
**Entry Criteria (Начало тестирования):**
- Код приложения успешно собирается и разворачивается через `docker compose up -d --build`.
- Тест-кейсы и чек-листы актуализированы в TMS (Qase.io).
- Тестовая база данных пуста и готова к наполнению.

**Exit Criteria (Окончание тестирования):**
- Выполнен 100% прогон (Test Run) обязательных тест-кейсов в Qase.io.
- Все найденные дефекты (Bug Reports) уровня `Critical` и `High` зафиксированы в баг-трекере (GitHub Issues).
- Результаты тестирования (тест-кейсы и отчеты) экспортированы в формате PDF/Markdown в репозиторий проекта.
