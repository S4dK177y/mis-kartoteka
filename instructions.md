# Инструкции для агента (Antigravity)

Данный файл содержит важные инструкции по работе с проектом МИС Картотека. Пожалуйста, внимательно читайте этот файл каждый раз перед началом работы над новыми задачами в этом проекте.

## 1. Лаунчер (Управление сервером)
В проекте есть приложение-лаунчер на базе Electron, находящееся в папке `launcher`. 
Оно служит для удобного запуска бекенд-сервера и открытия приложения в браузере.
- В случае, если вы добавляете новые зависимости для бекенда или меняете структуру запуска, убедитесь, что лаунчер продолжает корректно работать.
- Исполняемый файл лаунчера для конечного пользователя собирается командой `npm run build` из папки `launcher` и попадает в `dist/win-unpacked`.
- **ВАЖНО**: Лаунчер (через бекенд) раздает статические файлы фронтенда из папки `frontend/dist`. Если вы вносите изменения в React (фронтенд), вам ОБЯЗАТЕЛЬНО нужно выполнить `npm run build` в папке `frontend`, иначе лаунчер (и бекенд) будут отдавать старую версию приложения.
- Обращайте внимание на `package.json` в `launcher`, в частности на `productName`, которое должно соответствовать названию приложения.

## 2. Поддержание чистоты (Git и файлы)
- Если в процессе работы создаются временные файлы или папки с билдами (например, `dist` или `build`), убедитесь, что они добавлены в `.gitignore`, чтобы не засорять репозиторий.
- При завершении крупных блоков задач создавайте коммиты в Git с понятными описаниями (если проект использует Git).

## 3. Схема данных и миграции
- Проект использует Prisma ORM и SQLite (`backend/prisma/schema.prisma`).
- При любом изменении схемы базы данных необходимо выполнять команду `npx prisma db push` в папке `backend`.
- Не удаляйте старые данные без необходимости. Относитесь бережно к базе данных.

## 4. Файловое хранилище (Документы)
- Файлы загружаются в `data/storage`. Папка `data` должна быть в `.gitignore`.

## 5. Общие правила работы
- Соблюдайте текущий стиль кода и дизайн. Для фронтенда используется CSS с кастомными переменными (`index.css`), и Lucide React для иконок.
- Всегда проверяйте свою работу (verify), чтобы не оставлять сломанный интерфейс.
